整理日期：2026-11-17。文档版本：1.0。适用范围：已提供的中育教师端、优课畅学 APK，以及后续云笔记、在线专栏和随身答相关分析与学生账号测试记录。

## 2. 学校发现、服务器地址和通用请求规则

### 2.1 学校发现

```http
GET https://hagateway.zyai.cc/api/discovery/{school}
```

`school` 为学校代码。已记录的 `sxz` 路由为：

```json
{
  "name": "江苏省锡中",
  "server": "http://sxz.api.zykj.org",
  "webServer": "http://sxz.school.zykj.org"
}
```

上例省略了非必要字段。实际学校发现响应还观察到 `lcid`；早期静态 `GatewayBean` 中另有 `code` 字段线索，不能把 DTO 和实际响应字段视为完全一致。此接口的已记录响应是普通 JSON，不使用后文的 ABP 成功封装。

业务接口通常相对发现结果的 `server` 拼接。不要把默认发现网关当成所有业务的服务器，也不要把一个学校的地址硬编码为所有学校通用地址。

此前连接记录中，该学校官方网关给出 HTTP 地址；其 HTTPS 证书校验不通过。家书使用用户明确同意的 HTTP 连接，不跳过证书验证。该结果是已有测试快照，不表示证书以后不会修复。

优课 APK 还包含 `https://ykcx-pad.zyai.cc/`、HTTP 学校路由和开发分支配置。这里仅保留静态线索，不将其作为当前账号已验证可用的替代服务器。

### 2.2 已使用的请求头

```http
AppName: WebClient
AppVersion: 0
ClientCode: <登录响应中的值；缺省时为空>
Authorization: Bearer <学生访问令牌>
Content-Type: application/json
```

登录请求不携带先前的 Bearer 令牌。早期只读脚本也使用过 `AppName: com.zhongyukejiao.learningexpert`、`AppVersion: 10106`；后续家书测试和当前实现使用上面列出的 `WebClient/0`。这些头是客户端上下文，不是提高账号权限的凭据。

学校令牌仅发送给对应学校 API；下载 OSS 图片和上传对象时使用独立客户端，不能把学校 Bearer 头带到存储地址。家书已禁用带认证请求的自动重定向。

### 2.3 响应封装

普通平台接口和登录使用过以下 ABP 风格封装，示例仅说明形状：

```json
{"success": true, "result": {"example": "placeholder"}, "error": null}
```

SelfStudy 与 CloudNotes 使用 `code`、`msg`、`data` 风格：

```json
{"code": 0, "msg": "操作成功", "data": {"example": "placeholder"}}
```

CloudNotes 的 `data` 在已验证请求中通常为编码后的 Base64 字符串，必须按第 5.1 节解码；不能把 SelfStudy 的普通 JSON 处理方式直接套上去。`HTTP 200` 本身不是业务成功判据。

## 3. 登录、会话与身份标识

### 3.1 已验证的学生账号密码登录

```http
POST {server}/api/TokenAuth/Login
Content-Type: application/json
```

```json
{
  "userName": "<学生账号>",
  "password": "<学生密码>",
  "clientType": 1
}
```

成功处理至少核对 `success=true`、`result.accessToken` 和 `result.roleType=1`。`clientCode` 可能为空。存在新设备验证或修改密码要求时，应完成官方流程；不能仅因为获得部分响应字段就认为登录已经完成。

**家书 0.2.1 的会话恢复：** 当前学校的实测 JWT 签发至到期相隔 7200 秒。家书按令牌实际 `exp` 判断，在同步时提前 2 分钟使用正常登录接口更新；遇到 HTTP 401 时最多重试一次业务请求。HTTP 403 不作为自动重登依据，网络超时不直接重放写请求。密码、令牌、HTTP 同意选项仅保存在 Android 安全存储，退出时删除；旧版升级需要手动登录一次才能保存密码。

前后台同步受同一账号的 SQLite 租约约束，并从安全存储读取最新令牌。安全存储写入另有不含凭据的 SQLite 互斥锁，配合登录代次校验，防止退出或切换账号时被旧自动登录结果覆盖。错误密码、官方验证要求或新令牌仍被拒绝时，停止自动重登并提示；网络故障则退避重试。自动恢复真实测试已验证：无效令牌触发 401 → 正常学生登录一次 → 两次只读云笔记查询成功，第二次没有重复登录。实现见 `lib/auth.dart`，测试见 `test/live_auth_test.dart`。

当前家书代码检查 `needSmsVerification` 与 `needChangePwd`。旧教师端静态报告写有 `needSmsVerify` 分支名称；这些是不同来源的命名记录，尚未证明不同版本的字段完全一致，接入其他版本时需要核对实际 DTO 和响应。

教师端静态登录构造还出现 `role=2`、`clientType=2`、`im=false`、`smsVerificationCode`、`deviceNumber` 等字段。它们属于教师客户端线索，不能复制到学生请求中期待获得教师权限。

### 3.3 两种用户 ID 必须区分

| 标识 | 来源 | 用途 |
|---|---|---|
| 平台用户 ID | 登录 JWT 中的 `http://schemas.xmlsoap.org/ws/2005/05/identity/claims/nameidentifier` | 与 CloudNotes 返回的 `userId` 核对；对象存储签名使用该身份 |
| SelfStudy 用户 ID | `/SelfStudy/api/Account/Info` 的 `id` | 优课业务内的学习、监督等上下文 |

本次账号中两者不同。早期记录里的 `ContextMatchesTokenIdentity=false` 反映了混用了不同业务 ID，后续核对平台身份后确认云笔记归属于当前账号；它不是已确认的跨账号数据泄露。

客户端解码 JWT 是读取身份声明，不是代替服务器验签和鉴权。对返回资源还应核对平台用户 ID、学校和对应笔记 ID。

## 5. 云笔记 CloudNotes 接口与编码

### 5.1 请求和响应编码

以下是兼容已提供客户端的格式，不是登录凭据或安全的端到端加密方案。来源为教师 APK `yd/a.java`、`yd/b.java`、`yd/d.java`，以及已经实际使用的 PowerShell/Dart 实现。

1. 按 `Asia/Shanghai`（UTC+8）取当日年 `Y`、月 `M`、日 `D`，不能直接使用手机所在时区的日期。
2. 固定字符表如下，按原始 ASCII 字符使用：

```text
:F0wKU!Qg3}UkbW+w[:9|D3-5h=:T;7t#_GZ4#G;~ZNSq{8;}QIP>'{q.lje
```

3. `offset = (Y × M × D) mod 60`。
4. `first = ASCII字符(((D × M × 33 + 33) mod 94) + 33)`。
5. 将字符表从 `offset` 起旋转；密钥是 `first + 旋转后前14字符 + 字符表[D+M]`，下标从 0 开始。
6. 使用 UTF-8、AES-128/ECB、PKCS7 填充，密文转 Base64。

POST：先将请求对象序列化为 JSON，再编码；HTTP 请求体直接放 Base64 字符串，**不要额外包一层 JSON 双引号**。已用请求头仍是 `Content-Type: application/json`。

GET 参数：`Resources/GetByFileId` 的已验证形式，是先编码明文 `fileId=<笔记ID>`，再将 Base64 直接放到 `?` 后面。它不是 `?fileId=<编码值>`。本次脚本额外调用 URL 转义后出现过 500；去掉额外转义后成功。不同 HTTP 库的 URL 处理应按实际发出的字节核对，不能重复编码。

成功响应形状：

```json
{"code":0,"msg":"操作成功","data":"<Base64编码的JSON>"}
```

只有在业务 `code=0` 且 `data` 为非空字符串时按上述方式解码。密钥日期跨午夜可能变化，失败后的核对和重试须使用当前日期；不能因此创建新的重复消息 ID。

用于本地兼容性校验的固定测试向量（不是线上请求或真实消息）：

```text
时间：2026-11-17T04:00:00Z
明文：{"hello":"家书"}
密文：+XEkh506/b4v+cxrcLp7pu2h4SH844tG/cIGLQKv3K0=
```

### 5.2 获取笔记与目录元数据

```http
GET {server}/CloudNotes/api/Notes/GetAll
```

不带对象 ID，请求当前账号元数据。解码后的顶层字段：

| 字段 | 已知含义 |
|---|---|
| `userId` | 平台用户 ID；必须与当前登录身份核对 |
| `schoolCode` | 学校代码 |
| `totalCount` | 返回元数据中的总数 |
| `noteList` | 目录、笔记等记录数组 |

`noteList` 项字段：

| 字段 | 说明 |
|---|---|
| `fileId` | 记录 ID；本次新建目录使用 32 位小写无连字符 UUID |
| `fileName` | 显示名称 |
| `fileUrl` | 记录的文件/资源地址；目录为空字符串 |
| `parentId` | 父目录 ID；本次根目录使用字符串 `"0"` |
| `type` | 文件类型；目录 `0`，本次已有原生笔记为 `12` |
| `createTime`、`updateTime` | 创建和更新字段；实际类型/时区按返回值处理，不视为统一时间戳规范 |
| `version` | 版本信息；可与标题和更新时间共同用于变化检测 |
| `shared` | 共享标记；家书只采用明确未共享的专用目录 |
| `isRecycleBin` | 回收站标记；收件时排除回收记录 |
| `expirationTimeStamp` | 到期相关字段；完整业务语义尚未验证 |

一次历史基线观察到 10 个目录和 666 条 `type=12` 记录，仅用于确认格式，不能把该数量当成账号的恒定状态。家书获取全量元数据后，只读取专用目录内的笔记页面，不读取其他目录的正文。

### 5.3 创建或更新目录

## 6. 对象存储上传凭证与已知限制

### 6.1 获取临时上传凭证

```http
POST {server}/api/services/app/ObjectStorage/GenerateTokenV2Async
```

本次新建自有 TXT 对象实际使用的普通 JSON 请求（不做 CloudNotes 请求体编码）：

```json
{
  "fc": 1,
  "ft": 1,
  "fe": ".txt",
  "fr": 1,
  "fo": "0",
  "nonce": "<32位UUID>",
  "ts": 0,
  "sign": "<大写MD5摘要>"
}
```

`ts` 示例中的 0 仅为占位，实际为 Unix 毫秒时间戳。已测试组合对应的签名明文是：

```text
<平台用户ID>+note_v2+res+1+.txt+0+<nonce>+<ts>
```

其中 `+` 是实际分隔字符，整体按 UTF-8 计算 MD5，再输出大写十六进制。该计算不是账号认证，仍需要正常有效的学生令牌。其他类型组合没有因这个测试而自动得到验证。

响应结果观察到 `strategy`、`appId`、`bucket`、`endpoint`、`region`、`accessKeyId`、`accessKeySecret`、`securityToken`、`expiration` 等字段；`strategy` 为 `AliOss`。本文只列字段名，不保留任何密钥值。

测试对象键形状：

```text
note_v2/res/<平台用户ID>/<中国日期yyyyMMdd>/<nonce>.txt
```

### 6.2 OSS 请求

测试脚本使用 HTTPS、临时 OSS 凭证和 OSS V1 HMAC-SHA1 签名。签名文本按以下顺序拼接，换行分隔：

```text
HTTP方法
Content-MD5（本次为空）
Content-Type
Date
CanonicalizedOSSHeaders + CanonicalizedResource
```

已用头包含 `x-oss-security-token`；禁止覆盖时还有 `x-oss-forbid-overwrite:true`，OSS 头按规则规范化。资源路径是 `/<bucket>/<objectKey>`，Authorization 形状是 `OSS <AccessKeyId>:<Base64-HMAC-SHA1>`。学校 Bearer 令牌不参与 OSS 请求。

这是历史联调采用的签名方式，不是对所有 OSS 桶、区域或新版本签名要求的完整规范。

## 9. 家书使用约定及实现边界

这一节是家书自己的兼容协议，不是中育官方消息协议。

### 9.1 云笔记短笺格式

- 在根目录建立明确未共享的专用 `家书` 目录。
- 每条家长消息使用独立 32 位无连字符 UUID。0.3.3 起笔记 `fileId` 直接使用该 UUID；旧版本的 `h` 加消息 UUID 数值的 36 进制表示（左侧补 0 到 32 位）仅保留读取兼容。话题目录也直接用 UUID 作 `fileId`。0.2.0/0.2.1 写根目录笔记，0.3.0 起按当前选定话题设置 `parentId`。旧目录短笺继续作为话题读取。
- 0.3.6 新建笔记及话题目录使用 `爸爸：<正文>` 或 `妈妈：<正文>`，同步按独立的 `fileId` 区分同名对象。
- 正文当前限制为 1–60 个 Unicode 码点的单行文字；UI 也限制输入长度。
- 旧版标题的 `【JS1:<消息UUID>】` 后缀仍按对应版本的文件编号核对。新格式按 32 位十六进制文件编号和标题开头的署名识别。爸爸/妈妈署名是同一学生账号下的显示约定。
- 孩子在当前话题目录新建笔记发言，保存、同步；新建子目录表示分支话题，其名称也承载内容。0.3.0 遍历家书私有目录树，同目录笔记彼此平级，不被默认合并为目录消息附件。

### 9.2 同步、重试和提醒

- 先拉取远端记录，再核对本地待发送项；发送请求超时后继续使用原 UUID，避免盲目生成重复消息。
- 待发送记录的同一 ID 如已在远端改名或移走，停止重发，避免覆盖用户修改；已同步记录的目录移动只更新归属，不重复创建消息或发出新消息提醒。
- “服务器已保存”表示回读确认，不是送达或已读回执。
- 首次历史同步静默；后续新增或发生变化的孩子记录产生未读提示。原生笔记以页面截图呈现，不做 OCR 承诺。
- 前台约每 30 秒轮询，后台接收服务约每 3 分钟轮询。前后台共用同步锁，发生错误后按退避时间重试。
- 系统通知使用家书本地通知，不是已确认接入了中育推送。孩子未同步、网络不可用、系统省电或强制停止 App 时，不能保证及时接收。

### 9.6 话题目录与平级笔记消息（家书 0.3.0）

目录本身是内容载体，同时组织一个话题；该目录中的每条原生笔记都是独立发言，兄弟笔记彼此平级，多页笔记仍是一条消息。子目录表示一个分支话题。`parentId` 只表示所属话题，不隐含“回复上一条笔记”或精确引用关系。

家长在家书点击“开启话题”时创建 `type=0` 目录，在话题内发送消息时创建 `type=12` 原生笔记，点击“开分支”时创建子目录。两类记录沿用可读正文加 `JS1` 标记的名称与稳定 ID，不要求孩子手动填写协议编号。孩子直接在对应目录新建笔记回复，只有另开分支才需要建目录。

本地 SQLite 升级到版本 2，在消息表增加 `kind,remoteId,topicId,contentVersion,resourceCheckedAt,deleted,edited`。`kind` 区分目录话题和笔记，`remoteId` 是云端记录 ID，`topicId` 是父话题的云端目录 ID；空字符串代表本机视图中的家书根目录。迁移保留旧聊天记录、未读和待发内容，不自动搬动云端资料。首次树形同步静默导入历史，既有根目录笔记仍作为日常消息呈现。

同步规则：

- `GetAll` 元数据以 `parentId` 建立索引，只从已确认私有的家书根目录向下遍历。共享分支、重复 ID、孤立环和挂在笔记下面的非法子节点不作为可写话题。
- 目录名变化是话题内容编辑；笔记标题或资源摘要变化是原消息编辑。目录移动更新 `topicId`，不因更新时间变化而重复提醒。
- 新笔记或元数据变化立即查询资源；未变化的旧笔记满 5 分钟后按最久未检查顺序轮询，每轮最多额外检查 20 条。大量历史笔记时资源重新检查可能更久。MD5 摘要变化刷新图片缓存。
- 图片暂未同步时先显示笔记标题，不合并成父目录附件；页面稍后到达不会再新增同一条消息。一条笔记资源失败不阻塞其他分支。
- 离线创建的话题、分支和消息进入持久化待发队列，先确认父目录再创建子项；丢失创建响应时先按稳定 ID 回读。目的话题删除、移出或冲突时停止发送，不回退到根目录。
- 已删除或移出的记录保留本机历史并标示不可用，不据此推断 OSS 物理文件已删除。当前话题标为已读不会清除其他分支消息的未读。

实际服务器测试：在新建隔离测试根目录下创建话题和分支，分支中创建两条平级原生笔记；父子 ID、18 项资源下载 MD5 与重复同步检查通过，随后按叶到根删除本次新建笔记及目录索引。测试使用现有学生身份，没有移动、删除原有学习资料。对应测试代码是 `test/live_account_test.dart`。学生平板上的实际阅读和回信仍待设备联调。

### 9.7 原笔记续写提醒（家书 0.3.1）

孩子可以在已有原生笔记中续写后保存、同步。家书继续使用原有 `GetAll` 和 `Resources/GetByFileId`，不改写远端笔记。SQLite 升至版本 3，新增独立的 `bodyDigest` 资源摘要，排除仅改标题或移动目录引发的续写误报。首次取得旧笔记摘要时静默建立基线；后续资源摘要变化，在同一事务内更新原笔记并插入 `kind=update` 的本地未读消息，触发声音、振动和系统通知。父母署名的笔记同样适用；更新消息不参与远端 fileId 到原笔记的索引，不会上传为另一份笔记。

用户已确认 **C 可见且内容正常，D 不可见**。结合 A/B，当前设备上的结果为：32 位十六进制 ID、版本 1 的四资源和九资源笔记均能打开；测试使用的 h 开头 33 位 ID 即使版本 1 也不可见。九资源图片模板不需要仅因资源数量不同而重做。该对照证明测试组合的兼容性，不足以断言平台只按长度判断；尚未获得 1.13.6 客户端源码或设备日志来定位确切过滤规则。

0.3.3 新笔记直接使用 JS1 协议中的 32 位 UUID 十六进制值作 `fileId`，保留 type=12、九资源结构，并将资源索引地址和 fileUrl 登记为测试 C 使用的 HTTP 形式；实际 OSS PUT 和家书预览 GET 仍为 HTTPS。创建后核对资源，若版本 0 则以原五字段补登记并确认至少版本 1。不能把版本 1 当作学生已读凭证。

旧 h+32 位映射保留为 `NativeNote.legacyFileId`，用于已登记历史笔记的识别、内容更新和去重；不自动复制、删除或补登记这些旧笔记。仅尚未在服务器登记且不存在编号冲突的旧待发消息转为 32 位编号，先持久化目标再上传，响应丢失后按同一 ID 恢复。已有旧消息可在新版重新发送文字；不把旧正文图片重新生成而假称保留了孩子的修改。两个远端对象即使具有同一个协议标题，也分别保存历史，避免交替覆盖内容。

升级待发消息前额外回读包含回收站的完整索引；任一旧／新编号已存在（包括回收状态）则停止转换并标记冲突，避免复活已删除消息。45 项本地测试与静态分析通过，真实账号隔离测试确认两条新 32 位笔记均达到版本 1、资源登记为 HTTP 且实际下载采用 HTTPS，18 项内容摘要一致；测试索引已清理。最终 APK 发出新消息、孩子续写和家长提醒仍需安装后的完整实机验收。

### 9.10 本机删除消息（家书 0.3.4）

用户选择仅从家书删除、保留云笔记原件，因此不调用 Notes/Delete、资源删除或 OSS DELETE。消息菜单支持删除普通笔记消息及单独更新提醒，暂不删除话题目录。普通消息删除时按消息 ID 和 remoteId 记录本机隐藏标记，并清除该原消息和关联更新的未读状态；更新提醒仅按事件 ID 隐藏，因此不会阻止下一次正文变更提醒。待发／结果不明的消息改为 cancelled，停止后续发送；已存在的云端副本不会撤回。

标记保存在既有 settings 表，使用 account 范围及 `hide:id:`、`hide:remote:` 键，无须升级数据库结构。同步和数据库写入两处均检查标记，避免元数据变化、重新同步或迟到响应使记录再次显示。操作取得与前后台同步相同的 SQLite 租约；同步占用时提示稍后操作。删除只隐藏界面并保留历史身份，不是物理擦除或跨手机同步；退出登录不清理标记，卸载／清除应用数据会清除标记，尚无恢复入口。

验证：49 项离线测试通过；Android API25 集成测试验证菜单、确认／取消、单独删除提醒、删除原消息、后续内容变化不再恢复隐藏记录，以及原有安全存储、通知和后台服务生命周期。测试使用虚构账号与本地数据库，没有向学校服务器发出删除请求。

### 9.11 本机删除话题目录（家书 0.3.5）

沿用用户选择的本机隐藏范围，不调用云端删除接口。目录卡片和当前目录右上角均提供删除菜单；确认文案明确涵盖全部子目录、消息和更新提醒。事务内遍历当前账号本地目录树，对整棵子树记录消息／远端 ID 隐藏标记及 `hide:topic:<目录ID>`，清除未读并取消 queued/uncertain 发送任务；关联更新即使位于另一个历史话题也一并隐藏。其他话题和账号保持不变。

同步构造 NoteTree 时跳过被隐藏的目录及其遍历，后续新增的云端子目录／笔记不会被导入或提醒；既有被隐藏子项移出该目录后仍按对象 ID 保持隐藏。从当前目录内部删除后跳转到仍存在的上级，否则回到日常消息，同时清理被隐藏话题的本机草稿。云端目录与笔记原件始终保留，数据库结构不变。

验证：51 项本地测试与静态检查通过；Android API25 集成测试覆盖目录卡片删除菜单、取消保留子树、当前目录删除后返回日常消息、关联未读清除及无关历史保留。后台同步仍为每分钟一次，本轮没有使用真实学校服务器做任何删除操作。

### 9.12 正文页面编辑（家书 0.3.6）

家长或孩子在家书私有目录内的已同步笔记均可编辑。家书以选中的预览图为底图，将原笔迹和本次编辑合成为原生图片页。先把新资源上传到独立对象路径，再按原 `pageName` 和 `pageIndex` 登记正文图、预览和模板。登记时一并标记该页被替换的旧资源，其他页的资源不参与写入。最后使用原笔记编号、标题、父目录和文件地址更新索引，回读核对资源及版本。

本地模拟服务覆盖多页笔记中单页替换、保留原名、拒绝过期编辑、保存响应丢失后的回读。学校服务器对旧页资源删除标记的处理、多设备同时编辑，以及学生平板实际打开效果仍需端到端验证。服务端没有已确认的条件更新接口。

## 10. 错误处理与复测要求

| 响应/现象 | 已知解释 | 正确处理 |
|---|---|---|
| ABP `success=true` 或业务 `code=0` | 对本次请求的成功判据之一 | 还要核对身份、对象和读回结果 |
| HTTP 200 + 非零业务码 | 业务未成功 | 不显示发送成功 |
| `1001` | 本次 TXT 登记为请求参数有误 | 不认定为已写入，也不据此推断越权 |
| `1004` | 所测优课目录接口没有相关数据 | 权限未定，不等于接口不可用 |
| `1015` | 所测请求没有执行权限 | 保持当前身份，不进行角色伪造 |
| `1022` | 所测课程未授权 | 仅在合法课程上下文下复测 |
| `9999` | 所测教师搜索发生业务异常 | 不能当成明确权限结论或已确认漏洞 |
| HTTP 401/403 | 会话失效或该请求被拒绝 | 提示重新登录/通路不可用；不能无限快速重试 |
| HTTP 404 | 当前路由、版本或部署未提供该请求 | 不推断整个平台不存在同类功能 |
| HTTP 500 | 服务端处理失败；一次资源查询与重复 URL 编码有关 | 核对请求格式；不将错误本身等同于可利用漏洞 |
| OSS PUT 成功、元数据登记失败 | 两个独立步骤 | 不显示为可见笔记，记录并清理自有测试残留 |
| 请求超时 | 是否已写入不确定 | 先按原 ID 查询确认，再决定是否重试 |

后续测试应记录应用版本、学校、身份类型、HTTP 方法、路径、参数的来源、业务码和对象范围。不在日志里输出密码、令牌、临时存储密钥和私人内容。现有真实账号测试没有采用猜测 ID、修改学校白名单或提升账号角色的方式。
